{%- comment -%} The four ways to run Labs64.IO, as described in the documentation's Get Started page. {%- endcomment -%}

Pick your path

No account, license key or sign-up. Everything is open source and runs on your own machine or cluster.

See it running

Quickstart

One script installs the platform on any Kubernetes cluster and sends a real request through it.

  • You need: kubectl, Helm 4, a cluster (a local one is fine)
  • First result: about 5 minutes
Open the Quickstart → Try one service

Run one module locally

AuditFlow on Docker Compose, no Kubernetes needed.

  • You need: Docker, just, JDK 25, Maven
  • First result: a few minutes
Run AuditFlow → Run it for your team

Deploy to your cluster

AWS, Azure, GCP or on-premises, with your own identity provider and data stores.

  • You need: a cluster and the infrastructure you intend to keep
  • First environment: an afternoon
Plan a deployment → Change the code

Run the full ecosystem

Every repository, built from source on a local k3d cluster.

  • You need: Docker, and VS Code or a handful of CLI tools
  • First build: one long build, then minutes
Set up the workspace →

The Quickstart is an evaluation install with a demo identity provider. Keep it on a local or private cluster. Not sure which path? Compare the paths.
